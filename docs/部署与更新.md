# 部署与更新

本文档面向 Linux 服务器。目标是用最少步骤完成首次部署、更新、回滚和排障，不依赖本地构建镜像。

## 1. 前置要求

- Docker 24+
- Docker Compose v2（`docker compose version` 可用）
- 能访问 `ghcr.io`
- 建议 2 GB 内存；只跑 app + 内置 PostgreSQL + Redis 时，1 GB 也可尝试

仓库根目录执行：

```bash
./scripts/deploy.sh doctor
```

## 2. 首次部署

### 2.1 最小部署：app + PostgreSQL + Redis

```bash
./scripts/deploy.sh install
```

脚本会自动：

1. 从 `.env.example` 生成 `.env`
2. 生成 PostgreSQL / Redis 密码、管理员密码、凭证加密密钥、机器人 webhook token
3. 创建 `config/`、`logs/`、`.deploy/`
4. 拉取 `ghcr.io/mnwlzf/monitor:latest`
5. 启动 `app + postgres + redis`
6. 等待健康检查

完成后访问：

```text
http://<服务器IP>:8080
```

管理员账号默认 `admin`，初始密码会在首次安装时打印，同时保存在 `.env` 的 `MONITOR_ADMIN_PASSWORD`。

> 首次安装后请立即备份 `.env`。`UPSTREAM_CREDENTIAL_KEY` 丢失后，已保存的上游账号密码无法恢复。

### 2.2 需要 QQ 机器人 / NapCat

```bash
./scripts/deploy.sh install --with-napcat
```

额外启动 `napcat`，并创建：

```text
napcat/qq/
napcat/config/
napcat/plugins/
```

`install` 只会在 NapCat 容器不存在时拉取镜像；已有 NapCat 不会被自动更新，避免意外更新导致 QQ 登录态失效。日常 `update` 也只更新 app。

登录方式：

1. 打开 Monitor →「机器人状态」
2. 未登录时页面显示二维码
3. 手机 QQ 扫码确认
4. 在 NapCat WebUI 配置 OneBot HTTP 服务端和反向 HTTP 上报（如尚未配置）

已有 QQ 号可写入 `.env`：

```dotenv
NAPCAT_ACCOUNT=123456789
```

不需要快速登录时留空即可。

### 2.3 使用已有 PostgreSQL / Redis

先准备 `.env`：

```bash
cp .env.example .env
```

填写：

```dotenv
DB_URL=jdbc:postgresql://<host>:5432/monitor
DB_USERNAME=monitor
DB_PASSWORD=<password>
REDIS_HOST=<host>
REDIS_PORT=6379
REDIS_PASSWORD=<password>
```

然后：

```bash
./scripts/deploy.sh install --mode external
```

`external` 模式只启动 `app`；加 `--with-napcat` 时再启动 `napcat`。

### 2.4 NapCat 数据目录

默认数据目录是部署目录下的 `./napcat`。需要沿用旧目录时：

```dotenv
NAPCAT_DATA_DIR=/app/napcat
```

Compose 会把它挂载为：

- `NAPCAT_DATA_DIR/qq` → `/app/.config/QQ`
- `NAPCAT_DATA_DIR/config` → `/app/napcat/config`
- `NAPCAT_DATA_DIR/config` → `/app/napcat-config`（app 只读）
- `NAPCAT_DATA_DIR/plugins` → `/app/napcat/plugins`

## 3. 日常更新

正常更新只拉取 GHCR `latest` 并重建 app：

```bash
./update-monitor.sh
```

等价于：

```bash
./scripts/deploy.sh update
```

脚本会：

1. 记录当前镜像 ID 到 `.deploy/last-image-id`
2. 拉取 `ghcr.io/mnwlzf/monitor:latest`
3. `force-recreate` app
4. 等待健康检查

不会构建本地镜像，也不会把 `latest` 改成 local tag。

## 4. 回滚

```bash
./scripts/deploy.sh rollback
```

回滚到上一次 `update` 前记录的镜像 ID。回滚会临时使用 `${MONITOR_IMAGE_REPO}:rollback` 标签，仅用于回滚，不参与正常部署。

## 5. 状态与日志

```bash
./scripts/deploy.sh status
./scripts/deploy.sh logs
```

## 6. `.env` key 检查与补齐

检查当前 `.env` 相对 `.env.example` 是否缺少 key：

```bash
./scripts/deploy.sh env-check
```

补齐缺失 key（不会修改已有 key 的 value）：

```bash
./scripts/deploy.sh env-fix
```

注意：

- `env-fix` 只追加缺失 key，不覆盖已有 value
- 模板中的占位值会提示需要人工检查
- `external` 模式会跳过 `POSTGRES_*`
- 历史未使用 key 会保留，不会自动删除

## 7. 部署模式

模式保存在 `.deploy/mode`：

| 模式 | Compose 文件 | 适用场景 |
| --- | --- | --- |
| `full` | `compose.yaml` | 新服务器，内置 PostgreSQL + Redis |
| `external` | `compose.external.yaml` | 已有 PostgreSQL + Redis |

NapCat 开关保存在 `.deploy/with-napcat`。

这些文件不进入 Git，属于每台服务器自己的部署状态。

## 8. 从旧服务器迁移

需要迁移：

1. `.env`
2. `config/`（如有外挂配置）
3. `logs/`（可选）
4. `napcat/` 或 `NAPCAT_DATA_DIR` 指向的目录（需要保留 QQ 登录态时）
5. `.deploy/mode` 和 `.deploy/with-napcat`（或在新服务器重新执行 install 指定参数）

数据库和 Redis 使用外部服务时，只需保证新服务器能访问原地址。

迁移后执行：

```bash
./scripts/deploy.sh doctor
./update-monitor.sh
```

## 9. 常见问题

### 拉不到镜像

```bash
docker login ghcr.io
./scripts/deploy.sh doctor
```

### app 不健康

```bash
./scripts/deploy.sh logs
```

优先检查 `.env` 中的 `DB_*`、`REDIS_*`、`UPSTREAM_CREDENTIAL_KEY`。

### 端口冲突

修改 `.env`：

```dotenv
APP_PORT=18080
```

然后重新 `./scripts/deploy.sh install`。

### 不想用 NapCat

不要加 `--with-napcat`，并保持：

```dotenv
MONITOR_BOT_ENABLED=false
MONITOR_NAPCAT_ENABLED=false
```
