# QQ 机器人平台功能清单（管理员 / 普通用户）

> 依据当前 `main` 分支代码整理，覆盖「确定性命令」和「自然语言（大模型）」两条入口。
> 两条入口共用同一套取数与权限判定：命令不依赖大模型，没配模型也能用；
> 自然语言只是把同样的能力交给模型去挑。

---

## 一、角色与准入

### 1.1 三种角色

| 角色 | 判定条件 | 能看到什么 |
| --- | --- | --- |
| **平台管理员** | 邮箱命中 Sub2API `role=admin`，**或**在监控后台「自定义管理员」名单里（两者取并集） | 全部平台数据 |
| **平台普通用户** | 邮箱在 Sub2API 用户缓存里（自定义管理员也算平台用户） | 只有**自己**的数据 + 自己**有权限**的渠道状态 |
| **访客（非平台用户）** | 没绑定 / 没匹配到平台邮箱，或邮箱不在平台用户列表里 | 完全没有平台功能，只当普通聊天机器人 |

身份解析顺序（`BotIdentityResolver`）：

1. **显式绑定**：用户发 `/绑定 <邮箱>`，写入 Redis（QQ 号 → 邮箱）；
2. **自动匹配**：没有绑定时，按 QQ 号匹配 Sub2API 用户邮箱（开关 `qq-local-part-match`）；
3. 拿到邮箱后再判角色：平台用户 / 管理员；两者都不命中就是访客。

### 1.2 「双重命中」——通道也要对

平台功能 = **身份命中** 且 **上下文命中「指定群」**：

| 消息通道 | 管理员 | 普通平台用户 | 访客 |
| --- | --- | --- | --- |
| 指定群 · 群聊 | ✅ | ✅ | ❌ |
| 指定群发起的临时会话 | ✅ | ✅ | ❌ |
| 好友私聊 | ✅ | ❌ | ❌ |
| 非指定群 · 群聊 | ❌ | ❌ | ❌ |
| 非指定群发起的临时会话 | ❌ | ❌ | ❌ |

要点：

- 「**指定群**」和「**白名单群**」是两个概念：白名单决定机器人**回不回**这条消息，指定群决定**能不能用平台功能**；指定群应当配成白名单的子集。
- 指定群留空 = **任何群都不给平台功能**（fail-closed），不会因为漏配而放开。
- 群里还需要 `@机器人`（若开启了「需要 @」），私聊/临时会话不需要。
- **没有平台功能时，平台命令一律回「这个命令我用不了…」**，不暴露权限体系的存在；只有「是平台用户但不是管理员」才会看到「平台级数据仅管理员可查」。

## 三、管理员专属功能（详细）

这些命令走 `platformOnly` 闸门：非平台用户回「未知命令」，平台普通用户回「平台级数据仅管理员可查」。

### 3.1 `/平台`（别名 `platform`、`overview`）——上游平台概览

- **数据**：所有未删除的上游平台（含已停用的）。
- **列**：平台、类型、账号数、异常数（`status != true` 的账号）、余额合计。
- **来源**：`MonitorChatTools.platformReport()`。

### 3.2 `/号池 [时间窗]`（别名 `pool`）——号池监控矩阵

- **时间窗**：`90m / 1h / 6h / 12h / 24h / 7d / 30d / 90d`，默认 `24h`；非法值回落到默认。
- **对象**：被标记为「号池监控源」且启用中的平台。
- **内容**：
  - 一、有流量的渠道（按请求数倒序，最多 20 行）：平台/账号、缓存率、首 TOKEN、每秒 TOKEN、请求数，右侧是**时间桶热力色块**（按缓存命中率着色）；
  - 二、无流量的渠道（只列名字）；
  - 备注：合计渠道数/请求数、色块含义说明。
- **细节**：时间桶超过 32 列时按相邻桶合并（组内按请求数加权平均缓存率），大约每 8 列标一次时间；列与配色对齐前端「号池 → 趋势矩阵」页。
- **空态**：没有号池监控源 / 号池里还没有账号 / 窗口内没有流量，分别有对应提示。
- **来源**：`PoolReportService.report(range)`。

### 3.3 `/采集`（别名 `ingest`）——号池直连库增量采集状态

- **内容**：游标 `usage_logs.id`、游标最后推进时间、最新明细时间、数据滞后（秒/分钟/小时/天）。
- **异常分支**：未启用（`SUB2API_DB_ENABLED=false`）、数据源没配全、没配密码、游标尚未初始化，各有明确提示。
- **来源**：`PoolReportService.ingestReport()`。

### 3.4 `/账号 <关键字>`（别名 `account`）——账号查询

- **匹配**：账号显示名或登录名**不区分大小写**模糊匹配；跨全部平台。
- **列**：账号、平台、状态（正常/异常）、余额、已用额度、最近采集时间。
- **空态**：不给关键字 → 用法提示；没匹配到 → 「没有找到名称包含…的账号」。

### 3.5 `/变更 [条数|关键字]`（别名 `changes`）——变更记录

- **条数**：默认 5 条，上限 20；纯数字参数当条数用（如 `/变更 20`）。
- **关键字**：`倍率`（只看渠道倍率变化）、渠道名、账号名、`使用中`（只看在用渠道）等。
- **排序**（刻意设计）：**警告优先**（倍率上调 / 渠道移除）→ **使用中优先** → 时间倒序。避免「新增渠道」这类噪声把涨价挤掉。
- **列**：时间、级别（⚠ 警告 / 信息）、平台、渠道、是否使用中、变更内容。
- **备注**：警告条数统计 + 使用提示（如「只看渠道涨价可以发 /变更 倍率」）。
- **数据**：变更事件表按账号查询后 join 渠道名（`group_name` 是查询出来的，不在事件表里）。

### 3.6 `/消耗 [条数]`（别名 `cost`、`用量榜`）——账号用量排行

- **条数**：默认 10，上限 30。
- **排序**：按累计消耗（`total_actual_cost`，缺失时退回 `total_cost`）倒序。
- **列**：账号、平台、余额、今日消耗、累计消耗、累计请求。
- **备注**：数据来自最近一次采集快照（给最晚时间）、被截断说明。
- **New API 特别处理**：上游没有「今日消耗」字段，用当天首末两条累计消耗差值推算；额度被重置导致差值为负时跳过，不展示误导数据。

### 3.7 `/异常`（别名 `abnormal`）——异常账号名单

- **判据**（与页面红色标记一致）：已停用、最近采集失败（`FAILED`）、部分成功（`PARTIAL`）、凭证失效（`authStatus=INVALID`）。
- **列**：账号、平台、原因、余额、最近采集时间。
- **空态**：全部正常时明确回复「所有账号状态正常」。

### 3.8 `/任务`（别名 `tasks`）——定时任务状态

- **列**：任务名、处理器、启用/停用、最近执行时间、执行结果（成功/失败/未执行）。
- **排序**：启用中的优先 → 最近执行倒序。
- **额外**：失败的任务单独列一段，带上最近一次的错误信息。
- **标题**：启用 x / 共 y。

### 3.9 `/订单 <账号> [起始日期] [结束日期]`（别名 `orders`）——平台用户订单

- **账号**：邮箱或用户名；日期可省略，**默认近 30 天**，上限 20 条。
- **汇总**：时间范围、订单数、到账合计、实付合计、退款合计。
- **明细列**：创建时间、类型、支付方式、到账、实付、状态、支付时间。
- **匹配不到 / 匹配到多个用户**时有对应提示（多用户时列出 ID、邮箱、用户名、角色供选择）。

### 3.10 `/用户余额 <账号>`（别名 `userbalance`）——平台用户余额

- **字段**：用户 ID、邮箱、用户名、角色、状态、余额、冻结余额、累计充值。

### 3.11 `/用户消耗 [日期]`（别名 `userconsumption`）——平台用户消耗排行

- **日期**：默认今天，支持 `昨天` / `前天` / `YYYY-MM-DD`。
- **汇总**：日期、有消耗的用户数、请求数、标准费用合计、实际消耗合计。
- **明细**：用户、请求数、Token、标准费用、实际消耗（默认 TOP 30）。
- **来源**：Sub2API 只读库（与号池直连库共用连接配置）。

## 四、管理员与普通平台用户共有

### 4.1 `/渠道状态 [时间窗]`（别名 `channelstatus`）

- **时间窗**：`90m / 1h / 6h / 12h / 24h / 7d / 30d / 90d`，默认 `1h`。
- **内容**：按「平台 / 分组」聚合的请求数、成功率、首 TOKEN、缓存率、状态。
- **可见范围**（对齐 Sub2API `scopeFilter`）：
  - 管理员：**全部**分组；
  - 普通用户：只有**自己有权限的分组** —— 订阅型分组要有有效订阅，标准分组默认公开，专属/受限分组需要落在 `user_allowed_groups` 里。
- **空态**：没配只读库 / 查不到你的平台账号 / 你没有可访问的分组，分别有提示。
- **来源**：`BotChannelStatusService`（数据来自 Sub2API 被动渠道监控 v2 的聚合表，本身不含用户身份）。

### 4.2 `/我的余额`（别名 `余额`、`balance`）

- **字段**：邮箱、余额、冻结、累计充值、账号状态、并发上限、最近活跃。
- **口径**：只查发送者本人，邮箱由服务端在构造工具时注入。

### 4.3 `/我的用量 [today|week|month]`（别名 `用量`、`usage`）

- **周期**：默认 `today`；`week`（近 7 天）、`month`（近 30 天），也接受「本周 / 近7天 / 本月」等中文写法。
- **指标**：请求数、输入 Token、输出 Token、缓存读取 Token、缓存写入 Token、总 Token、实际消耗、标准计费、平均耗时。

### 4.4 `/我的密钥`（别名 `密钥`、`keys`）

- **列**：名称、密钥（打码）、状态、额度、最近使用时间。

### 4.5 `/我的信息`（别名 `whoami`、`me`）

- 只回**当前绑定的邮箱**，不回角色、不回「是不是平台用户」——避免被用来枚举平台用户。

### 4.6 `/绑定 <邮箱>` / `/解绑`

- 绑定写入 Redis（QQ → 邮箱），是身份识别的第一优先级来源。
- **防枚举**：无论邮箱是否命中平台用户，回复完全一样（「已记录你的邮箱」），不会因为绑定成功/失败暴露谁是平台用户。
- 邮箱格式只做基本校验（够用即可）。

### 4.7 `/天气 <城市> [天数]`

- **所有人可用**（含访客），与平台无关。
- 天数 `0–7`（0 = 只要当前天气），不传取配置的默认天数。

### 4.8 `/画图 <提示词>`

- **所有人可用**（含访客）。
- **全局限频**：默认一分钟最多 3 张（可配），限频在生图服务里统一做——命令和自然语言走同一个闸门。
- 通过限频后先回一句「正在画，稍等」（一轮只发一次），避免用户以为机器人没反应。
- 提示词长度上限默认 400 字（可配）；生成失败的原文会兜底发给用户。

### 4.9 `/help`

- 按角色给三档不同的命令清单：管理员 / 平台普通用户 / 访客。
- 大模型不可用时，这条清单会被拼进「自然语言问答未启用」的提示里。

## 五、访客（非平台用户）能用什么

- `/绑定`、`/解绑`、`/我的信息`；
- `/天气`、`/画图`；
- 直接聊天（闲聊、常识、日期、农历、黄历等）。

**绝对禁止**：出现任何平台相关信息。访客人设的提示词里明确写了「平台 / 上游 / 账号 / 余额 / 额度 / 号池 / 密钥 / 监控 / 采集」是禁区，遇到就自然岔开，**不承认也不暗示存在这类系统**，更不会提「管理员 / 权限」。平台命令一律回统一的「未知命令」。

## 六、自然语言（大模型）侧的工具差异

机器人按身份选「人设」，不同人设挂载的工具集不同：

| 工具 | 能查什么 | 管理员 | 普通用户 | 访客 |
| --- | --- | :--: | :--: | :--: |
| `MonitorChatTools`（9 个） | 平台概览、号池概览/热力图、采集状态、账号明细、变更记录、用量排行、异常账号、定时任务 | ✅ | ❌ | ❌ |
| `BotOrderTools`（2 个） | 平台用户订单、平台用户余额 | ✅ | ❌ | ❌ |
| `BotUsageTools`（1 个） | 指定日期全平台用户消耗排行 | ✅ | ❌ | ❌ |
| `BotUserTools`（3 个） | 我的余额 / 我的用量 / 我的密钥 | ✅ | ✅ | ❌ |
| `BotChannelStatusTools`（1 个） | 渠道状态（按可见范围过滤） | ✅ | ✅ | ❌ |
| `WeatherTools`（1 个） | 天气 | ✅ | ✅ | ✅ |
| `ImageGenTools`（1 个） | 生图 | ✅ | ✅ | ✅ |

关键点：

- **平台级工具只挂给管理员人设**：普通用户和访客的客户端根本不注册这些工具，所以模型再怎么被诱导也调不到。
- `BotUserTools` / `BotChannelStatusTools` 是**每请求新建**的，身份（邮箱 / 是否管理员 / 可见用户 ID）在构造时注入，工具方法本身**不接受任何「查谁」的参数**，从根上堵死「传别人的 ID 越权查询」。
- 普通用户人设的提示词里明确写「平台级数据只有管理员能查，直接说明该数据仅管理员可查，不要猜测、不要编造」。

## 七、权限与安全设计小结

1. **双重命中**：身份命中 + 指定群上下文命中，缺一不可。
2. **不暴露权限体系**：访客看到的是「未知命令」，而不是「权限不足」。
3. **只查自己**：用户级工具按请求构造、不接受用户标识参数。
4. **可见范围过滤**：渠道状态按 Sub2API `scopeFilter` 过滤，管理员不过滤。
5. **工具级隔离**：平台级工具只挂在管理员人设上。
6. **记忆隔离**：会话记忆按「人设 + 通道 + 用户」隔离，群聊里不同人的上下文不会串。
7. **敏感操作不出机器人**：密钥/密码明文查看（reveal）只在 Web 管理端，机器人不提供。
8. **回复兜底**：超长回复自动渲染成表格/热力图图片，渲染或发送失败时退回截断文本。

## 八、相关配置项（页面可改，改完即时生效）

| 配置 | 说明 |
| --- | --- |
| 总开关 | 关掉后机器人忽略所有消息 |
| 白名单群 / 白名单 QQ | 留空 = 不限制；建议显式配置 |
| **指定群**（平台功能群） | 只有这些群及其临时会话才触发平台功能；**留空 = 一个都不给** |
| 需要 @ | 群里是否必须 @机器人 才响应 |
| 命令前缀 | 默认 `/` |
| 回复长度上限 | 超过就渲染成图片（表格/热力图） |
| 记忆窗口 | 会话记忆保留多少条消息 |
| 管理员来源 | Sub2API `role=admin` ∪ 监控后台自定义管理员名单 |

> 部署级参数（webhook 密钥、OneBot 地址等）仍在环境变量里，不在页面配置。
